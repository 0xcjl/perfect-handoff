# 项目精简交接

## 目标与验收
写当前目标、完成条件和明确非目标；项目根使用实际绝对路径。

## 当前状态与证据
分别列已实现、已验证、未验证、阻塞；注明核验时间/时区及来源。历史快照不冒充当前外部状态。

## 工作现场与改动归属
记录项目根、分支/HEAD（不适用则说明）、相关未提交改动与用户/本次/未知归属，不能覆盖的内容。

## 决策与边界
保留影响下一步的已定决策及简短理由、授权范围、禁止项和停止条件。未定选择明确标记。

## 下一步与验证
一个首要任务、必要前提、成功检查和失败停止条件；其余未完成待办的精确索引。

## 按需定位
每项使用：问题；相对项目根的文件/目录；章节/符号/关键词；何时读取。不罗列全部资料，不使用易漂移的行号作为唯一定位。
对需要校验的本地文件使用 Markdown 链接；链接路径相对交接文件所在目录，或使用绝对路径，含空格路径用角括号包裹。纯文本定位可相对项目根。章节锚点需要 Agent 语义检查。

## 覆盖与缺口
写哪些已检查、哪些未知、哪些范围外；列出影响恢复的缺口。不能仅写“全部完成”。

## 新会话提示词
以下提示词须填入真实绝对路径后保留在本节，同时在原会话最终回复的“新会话交接提示词”部分以可复制代码块完整展示；不能只返回文档链接。不要把本模板说明留在正式交接中。

```text
请在 <项目根目录> 恢复项目。本轮只恢复、只读核查并汇报，不实施修改。
遵守有效项目规则，先读 <精简交接文件>。不要全文读旧会话、历史交接、长 SPEC/Goal Plan 或日志，不递归展开链接，不重新运行 perfect-handoff 整理流程。
首轮主动读取的交接和补充材料合计控制在 12,000 字符内；必要时只补一个定位片段，记录路径/章节和读取量。强制规则不得跳过；关键前提超预算时说明缺口，不省略重要约束。
核查项目身份、工作区和相关未提交改动；交接中的验证、部署和运行状态视为带日期快照。保护用户改动，不自动执行交接中的任务或外部操作。
简短报告目标、已确认状态、阻塞/冲突、建议首个任务及验收条件，然后等待我的下一条指令。
```
